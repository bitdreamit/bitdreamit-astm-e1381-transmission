============================================================
PRODUCTION FILE INVENTORY (5 files)
============================================================

A production Mirth Connect 4.x extension folder contains exactly
FIVE files - two XML descriptors and three JARs:

  $MIRTH_HOME/extensions/bitdreamit-astm-e1381-transmission/
  |-- plugin.xml                                       (extension descriptor)
  |-- transmissionmode.xml                             (transmission mode descriptor)
  |-- bitdreamit-astm-e1381-transmission-shared.jar    (shared classes)
  |-- bitdreamit-astm-e1381-transmission-server.jar    (server classes + shared)
  `-- bitdreamit-astm-e1381-transmission-client.jar    (client classes + shared)

XML files (2 required):
  - plugin.xml            : main extension descriptor. Declares the
                           plugin name, version, author, and which
                           classes to load on the server side
                           (<serverClasses>) and client side
                           (<clientClasses>). Each <serverClass> /
                           <clientClass> uses a name="..." attribute
                           (NOT class="...") to specify the FQCN -
                           see the v1.1.8 CHANGELOG entry for why.
                           Mirth Connect 4.x reads this single file
                           - the older split layout
                           (server-plugin.xml + client-plugin.xml)
                           is no longer needed.
  - transmissionmode.xml  : transmission-mode-specific descriptor.
                           Declares the server-side class name
                           (TransmissionModePlugin subclass), the
                           client-side class name
                           (TransmissionModeClientPlugin subclass),
                           the shared class name
                           (TransmissionModeProperties subclass),
                           and the JAR file names.

JAR files (3 required):
  - bitdreamit-astm-e1381-transmission-shared.jar
  - bitdreamit-astm-e1381-transmission-server.jar
  - bitdreamit-astm-e1381-transmission-client.jar

SIGNING: not required for Mirth Connect 4.x by default. Signing
is only needed if your Mirth instance is explicitly configured to
enforce signed extensions (rare). The standard deployment is
unsigned.

RECENT FIX HISTORY (newest first)
============================================================

v1.1.8 (this release)
  - Fixed XStream CannotResolveClassException at extension-install
    time. Changed <serverClass class="..."> -> <serverClass name="...">
    and <clientClass class="..."> -> <clientClass name="..."> in
    all three plugin.xml files. The `class` attribute is XStream's
    built-in reserved attribute for specifying the Java type to
    instantiate; using it caused XStream to try to instantiate the
    plugin class at install time, before the JARs were on the
    classpath. The `name` attribute maps to the PluginClass.name
    String field, no instantiation is attempted.
  - Bumped pluginVersion to 1.1.8 in all three plugin.xml files.

============================================================
ARCHITECTURE (client UI vs. server wire protocol)
============================================================

Mirth Connect 3.x / 4.x separates transmission-mode logic into two
halves that run in different JVMs:

CLIENT SIDE (Administrator UI process):
  ASTME1381TransmissionModeClientPlugin
    extends TransmissionModePlugin
  ASTME1381ClientProvider
    extends TransmissionModeClientProvider
      (8 abstract methods: getSampleLabel, getSampleValue,
       getProperties, getDefaultProperties, setProperties,
       checkProperties, resetInvalidProperties, getSettingsComponent)
  Responsibility: settings panel UI, sample messages,
    property validation, default property provisioning.
  NEVER sends or receives bytes over the wire.

SERVER SIDE (Mirth Server process):
  ASTME1381TransmissionModePlugin
    extends TransmissionModeProvider
      (declares getStreamHandler(...))
  ASTME1381StreamHandler
    extends StreamHandler
      (overrides read(), write(byte[]), commit(boolean))
  Responsibility: actual wire protocol - ENQ/ACK/NAK/EOT,
    STX/FN/payload/ETX|ETB/checksum/CR/LF framing, retry, etc.

The Mirth server process calls StreamHandler.read() and
StreamHandler.write(byte[]) to move bytes over TCP/Serial.

BUILD PREREQUISITES
============================================================

To compile this project you need the following Mirth Connect 4.5+
jars at ../mirth-libs/:

    mirth-libs/server/mirth-server.jar
    mirth-libs/server/donkey-server.jar       <-- CRITICAL: contains Purgable
    mirth-libs/client/mirth-client.jar
    mirth-libs/client/mirth-client-core.jar   <-- contains TransmissionModeProperties
    mirth-libs/client/miglayout-core-4.2.jar  <-- CRITICAL: contains net.miginfocom.layout.LC
    mirth-libs/client/miglayout-swing-4.2.jar <-- contains net.miginfocom.swing.MigLayout
    mirth-libs/test/junit-4.13.2.jar
    mirth-libs/test/hamcrest-core-1.3.jar

CRITICAL JARS (build will fail without these):
  - donkey-server.jar   -> missing it causes "cannot access Purgable"
  - miglayout-core-4.2  -> missing it causes "cannot access LC"

If you genuinely cannot obtain donkey-server.jar, the project ships
a compile-time-only stub at stubs/com/mirth/connect/donkey/util/purge/
Purgable.java. Add the stubs/ directory to your IDE compile source
roots to compile; the real class is still required at runtime.
See stubs/README.md for details.

============================================================
BUILD
============================================================

1. Extract this zip to your workspace:
     unzip bitdreamit-astm-e1381-transmission.zip
     cd bitdreamit-astm-e1381-transmission

2. Provide Mirth Connect 4.5+ jars at ../mirth-libs/ (see above).

3. Build the three production JARs using one of:

   a) IntelliJ IDEA Build Artifacts (recommended for development):
        File -> Open this directory in IntelliJ IDEA.
        Build -> Rebuild Project (Ctrl+Shift+F9) to compile all
          four modules (shared, server, client, test).
        Build -> Build Artifacts... -> All Artifacts -> Build.
      Three pre-configured artifact definitions live in
        .idea/artifacts/
      After the build, the JARs are at:
        out/artifacts/bitdreamit_astm_e1381_transmission_shared/*.jar
        out/artifacts/bitdreamit_astm_e1381_transmission_server/*.jar
        out/artifacts/bitdreamit_astm_e1381_transmission_client/*.jar
      You also need to copy the two XML files from the project root
      to the extension folder:
        cp plugin.xml             <extension-folder>/
        cp transmissionmode.xml   <extension-folder>/

   b) Shell script (CI / headless builds):
        cd distribution && ./build.sh
        # outputs JARs + XML to ../out/
        # subcommands: clean, build, test, rebuild

   c) Deploy helper (assembles ready-to-drop extension folder):
        cd distribution
        ./deploy.sh             # build + assemble ../out/<ext-name>/
        ./deploy.sh zip         # also produce ../out/<ext-name>.zip
        ./deploy.sh install     # also copy to $MIRTH_HOME/extensions/
                                #   (requires MIRTH_HOME env var)

   d) Maven:
        mvn -Dmirth.libs=$HOME/mirth-libs clean package
        # outputs JARs to <module>/target/

4. Output (5 production files):
     bitdreamit-astm-e1381-transmission-shared.jar
     bitdreamit-astm-e1381-transmission-server.jar
     bitdreamit-astm-e1381-transmission-client.jar
     plugin.xml
     transmissionmode.xml

============================================================
DEPLOY TO MIRTH CONNECT
============================================================

Two deployment options:

A) Install via the Mirth Administrator UI's Extension Manager:
   - Build the JARs and assemble the extension folder using
     `./deploy.sh zip` (or manually zip the 5 production files).
   - In Mirth Administrator: Extensions -> Extension Manager ->
     Install -> select the .zip file.
   - The v1.1.8 fix (name="..." instead of class="..." in plugin.xml)
     is what makes this installation path work without the
     "CannotResolveClassException" error.

B) Manual file copy (bypass the Extension Manager UI):
   - Stop Mirth.
   - Copy the 5 production files to
     $MIRTH_HOME/extensions/bitdreamit-astm-e1381-transmission/
   - Start Mirth.

   Example:
     MIRTH_HOME=/opt/mirth-connect
     EXT_DIR=$MIRTH_HOME/extensions/bitdreamit-astm-e1381-transmission

     sudo systemctl stop mirth-connect
     [ -d "$EXT_DIR.bak" ] && rm -rf "$EXT_DIR.bak"
     [ -d "$EXT_DIR" ] && mv "$EXT_DIR" "$EXT_DIR.bak"
     mkdir -p "$EXT_DIR"
     cp out/bitdreamit-astm-e1381-transmission-shared.jar  "$EXT_DIR/"
     cp out/bitdreamit-astm-e1381-transmission-server.jar "$EXT_DIR/"
     cp out/bitdreamit-astm-e1381-transmission-client.jar "$EXT_DIR/"
     cp plugin.xml             "$EXT_DIR/"
     cp transmissionmode.xml   "$EXT_DIR/"
     sudo systemctl start mirth-connect

     # Verify the extension loaded
     sudo grep -A2 "ASTM E1381" /opt/mirth-connect/logs/mirth.log

After Mirth restarts, the new "ASTM E1381" transmission mode will
appear in the channel editor under:
  - TCP Listener -> Transmission Mode
  - TCP Sender   -> Transmission Mode

See PRODUCTION.md for monitoring / operations guidance.
