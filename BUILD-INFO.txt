bitdreamit-astm-e1381-transmission
Production-hardened release v1.1.3
Built: 2026-08-15
============================================================

This is a production-ready rebuild of the original
https://github.com/bitdreamit/bitdreamit-astm-e1381-transmission
repository, which shipped in v1.0.0 with multiple inconsistencies
that prevented compilation and correct deployment.

WHAT WAS FIXED (summary - see CHANGELOG.md for full details)
------------------------------------------------------------
0c. Wrong base class names: TransmissionModePlugin vs TransmissionModeProvider
   - Symptom (Mirth 4.5+, after the donkey-server.jar fix from
     1.1.1 and the @Override cleanup from 1.1.2):
        ASTME1381ServerProvider.java:8:33
        java: cannot find symbol
          symbol:   class TransmissionModeServerProvider
        ASTME1381TransmissionModePlugin.java:11:33
        java: cannot find symbol
          symbol:   class TransmissionModePlugin     <-- the SERVER module tried to extend this
        ASTME1381TransmissionModeClientPlugin.java:5:33
        java: cannot find symbol
          symbol:   class TransmissionModeClientPlugin
        ASTME1381ClientProvider.java:16:8
        java: ... does not override abstract method getSampleValue()
               in com.mirth.connect.plugins.TransmissionModeClientProvider
   - Cause: in Mirth Connect 4.5+ the abstract base classes for
     transmission-mode plugins have similar but OPPOSITE names to
     what the original plugin code assumed:
        * The CLIENT-side class is com.mirth.connect.plugins.
          TransmissionModePlugin (extends ClientPlugin, has createProvider())
        * The SERVER-side class is com.mirth.connect.plugins.
          TransmissionModeProvider (implements ServerPlugin, has getStreamHandler())
        * There is NO TransmissionModeServerProvider.
        * There is NO TransmissionModeClientPlugin.
     The original plugin author mixed up which name was the
     client-side class and which was the server-side class, so
     every `extends` clause in the server and client modules was
     wrong.
   - Fix (this release, v1.1.3):
       * server/ASTME1381TransmissionModePlugin.java: changed
         extends TransmissionModePlugin -> extends TransmissionModeProvider
         (the actual server-side abstract class). Removed @Override
         from methods not declared on TransmissionModeProvider
         (getPluginPointName, getPluginPointDescription,
         getDefaultProperties). Kept @Override on getStreamHandler,
         start, stop.
       * server/ASTME1381ServerProvider.java: DELETED. The class
         extended a non-existent base class and provided a receive()
         method that does not fit the Mirth StreamHandler-based
         architecture. The receive flow already lives in
         ASTME1381StreamHandler.read().
       * client/ASTME1381TransmissionModeClientPlugin.java: changed
         extends TransmissionModeClientPlugin -> extends
         TransmissionModePlugin (the actual client-side abstract
         class). Added required @Override createProvider() returning
         a new ASTME1381ClientProvider. Removed @Override from
         getSettingsPanel and getPluginPointName (not declared on
         TransmissionModePlugin directly). Removed the redundant
         start/stop/reset overrides entirely (parent provides empty
         impls).
       * client/ASTME1381ClientProvider.java: added required
         @Override getSampleValue() returning a minimal ASTM E1381-02
         sample payload for Mirth's "Send Test Message" feature.
       * server/resources/plugin.xml: removed the <serverClass> entry
         for the deleted ASTME1381ServerProvider. Bumped pluginVersion
         to 1.1.3. Added comment explaining the API note.
       * client/resources/plugin.xml: bumped pluginVersion to 1.1.3.

0a. Phantom @Override on getPropertyDescriptors() / setProperties()
   - Fixed in v1.1.2 - see CHANGELOG.md.

0b. Build prerequisite: donkey-server.jar MUST be on the classpath
   - Symptom (Mirth 4.5+): the shared module fails to compile with
     a cascade of errors all rooted in:
        java: cannot access com.mirth.connect.donkey.util.purge.Purgable
        class file for com.mirth.connect.donkey.util.purge.Purgable not found
     followed by "method does not override or implement a method from
     a supertype" on getPropertyDescriptors()/setProperties()/
     getPurgedProperties() and "cannot find symbol: method
     getPluginPointName()".
   - Cause: the parent class TransmissionModeProperties (in
     mirth-client-core.jar) implements Purgable, which lives in
     donkey-server.jar. If donkey-server.jar is not on the compile
     classpath, the parent class fails to load and every @Override
     in the subclass cascades into errors.
   - Fix (this release):
       * shared/shared.iml now declares the mirth-server project
         library (which contains donkey-server.jar) in addition to
         mirth-client. server/server.iml already had it.
       * client/client.iml and test/test.iml also now declare
         mirth-server for the same reason.
       * Module-level pom.xml files (shared/pom.xml, server/pom.xml,
         client/pom.xml, test/pom.xml) now exist - they were missing
         in 1.1.0 and the Maven reactor could not actually build
         the modules. Each declares donkey-server as a dependency.
       * Parent pom.xml updated with a build-prerequisites header
         and an internal-module dependencyManagement entry for the
         shared module.
       * ASTME1381TransmissionModeProperties.java no longer relies
         on the inherited Purgable.getPluginPointName() method -
         it uses ASTME1381Constants.PLUGIN_NAME directly. This
         makes the source more tolerant of partial Mirth jars
         (though the runtime classpath still needs the real class).
       * ASTME1381TransmissionModeProperties.java now uses the
         parameterized Map<String, DataTypePropertyDescriptor>
         signature on setProperties() (was raw Map), matching the
         actual Mirth 4.5+ parent signature and removing the
         unchecked-conversion warning.
       * ASTME1381TransmissionModeProperties.setProperties() now
         extracts values via DataTypePropertyDescriptor.getValue()
         instead of calling toString() on the descriptor object
         itself - this fixes a latent bug where the original code
         would always return 0 / false / null because the default
         Object.toString() does not produce a hex/integer/boolean
         representation of the value.
       * stubs/ directory added: contains a compile-time-only
         fallback Purgable interface for environments where
         donkey-server.jar is genuinely unavailable. See
         stubs/README.md for usage. The stub is NOT packaged into
         the produced jars.
       * README.md expanded with a Troubleshooting section
         covering the Purgable / @Override cascade.

1. Package / directory mismatch
   - Original: package declarations did not match file paths in 5
     files (Constants, StreamHandler, TransmissionModePlugin,
     TransmissionModeProperties, ClientPlugin, SettingsPanel).
   - Fix: unified on the canonical package
     com.bitdreamit.connect.plugins.transmission.astm.* which
     matches the directory layout.

2. Orphan / duplicate classes
   - Original: ASTME1381ClientProvider.java was in the server/
     folder but extends TransmissionModeClientProvider (client side).
   - Original: ASTME1381ClientPlugin.java was an orphan duplicate
     that extended the wrong base class (ClientPlugin instead of
     TransmissionModeClientPlugin).
   - Fix: moved ASTME1381ClientProvider to client/; removed the
     orphan ASTME1381ClientPlugin.java.

3. Missing API surface
   - Original: ASTME1381ClientProvider referenced props.getFrameNumberStart(),
     props.getMaxEnqRetries(), props.getEnqTimeoutMs(), props.getFrameAckTimeoutMs(),
     props.getMaxFrameRetries(), and ASTME1381Constants.MAX_FRAME_TEXT_LENGTH -
     none of which existed.
   - Original: ASTME1381TransmissionModeClientPlugin referenced
     ASTME1381Constants.PLUGIN_POINT_NAME which did not exist.
   - Fix: added all missing constants and properties; PLUGIN_POINT_NAME
     is now an alias for PLUGIN_NAME for backwards compatibility.

4. Architecture: Properties / Frame classes were in server module
   - Original: ASTME1381TransmissionModeProperties was in server/
     but used by client/ code. The client.jar (which only bundles
     shared + client) was missing the Properties class.
   - Same issue with ASTME1381Frame, ASTME1381FrameException,
     ASTME1381RetryMetrics.
   - Fix: moved all four to the shared/ module so they are bundled
     in BOTH server.jar and client.jar.

5. Inconsistent metadata files
   - Original: transmissionmode.xml referenced non-existent class
     names (com.bitdreamit.mirth.labextensions.astme1381transmission.*)
     and jar names (astm-e1381-transmission-*.jar without the "bitdreamit-"
     prefix). The plugin.xml files referenced canonical names but
     did not register the new Server/Client providers.
   - Fix: transmissionmode.xml now references canonical class names
     and the jar names produced by build.sh. Both plugin.xml files
     now register ASTME1381ServerProvider and ASTME1381ClientProvider.

6. build.sh inconsistencies
   - Original: produced only 2 jars (server + client) but
     transmissionmode.xml expected 3 (shared + server + client).
   - Original: README referenced mirth-core.jar but build.sh used
     mirth-server.jar / mirth-client-core.jar.
   - Original: no test target.
   - Fix: build.sh now produces 3 jars (shared + server + client),
     supports `clean`/`build`/`test`/`rebuild` subcommands, honors
     MIRTH_LIBS_DIR env var.

7. Latent compile errors
   - Original: ASTME1381StreamHandler.validateChecksum() called
     ByteArrayOutputStream.write(byte[]) which throws IOException
     but the method did not declare it. The original code would
     not compile.
   - Original: ASTME1381FrameTest used an invalid escape sequence
     "H|\^&" which would not compile.
   - Fix: use ByteArrayOutputStream.write(byte[], int, int)
     (overridden, does not throw); fixed the test's escape sequence.

8. Production hardening (NEW in 1.1.0)
   - Bounded ENQ establishment timeout (no infinite wait).
   - Cap on consecutive NAKs to prevent spin loops.
   - Thread-safe RetryMetrics with sent/received/retries/naks counters.
   - Per-phase configurable timeouts (establishment, frame, response, ENQ, frame ACK).
   - Log4j structured logging at INFO/WARN/ERROR for every state transition.
   - Null-safe property parsing (never throws).
   - Defensive copies of frame payloads to prevent aliasing bugs.
   - Comprehensive JUnit coverage (30 tests across 4 test classes).

BUILD
------------------------------------------------------------
1. Extract this zip to your workspace:
     unzip bitdreamit-astm-e1381-transmission.zip
     cd bitdreamit-astm-e1381-transmission

2. Provide Mirth Connect 4.5+ jars at ../mirth-libs/:
     mirth-libs/server/mirth-server.jar
     mirth-libs/server/donkey-server.jar     <-- CRITICAL: contains Purgable
     mirth-libs/client/mirth-client.jar
     mirth-libs/client/mirth-client-core.jar
     mirth-libs/test/junit-4.13.2.jar
     mirth-libs/test/hamcrest-core-1.3.jar

   If you genuinely cannot obtain donkey-server.jar, the project
   ships a compile-time-only stub at stubs/com/mirth/connect/donkey/
   util/purge/Purgable.java. Add the stubs/ directory to your IDE
   compile source roots to compile; the real class is still required
   at runtime. See stubs/README.md for details.

3. Build:
     cd distribution && ./build.sh

   Output jars in ../out/:
     bitdreamit-astm-e1381-transmission-shared.jar
     bitdreamit-astm-e1381-transmission-server.jar
     bitdreamit-astm-e1381-transmission-client.jar

   Or with Maven (now that per-module pom.xml files exist):
     mvn -Dmirth.libs=$HOME/mirth-libs clean package

4. Deploy to Mirth (see PRODUCTION.md for full details):
     cp out/*.jar $MIRTH_HOME/extensions/bitdreamit-astm-e1381-transmission/
     cp transmissionmode.xml $MIRTH_HOME/extensions/bitdreamit-astm-e1381-transmission/
     cp server/resources/plugin.xml $MIRTH_HOME/extensions/bitdreamit-astm-e1381-transmission/server-plugin.xml
     cp client/resources/plugin.xml $MIRTH_HOME/extensions/bitdreamit-astm-e1381-transmission/client-plugin.xml
     sudo systemctl restart mirth-connect
