============================================================
RECENT FIX HISTORY (newest first)
============================================================

v1.1.5 (this release)
  - Added miglayout-core-4.2.jar to the IntelliJ mirth-client library.
    MigLayout 4.2 ships as TWO jars (core + swing); the swing jar's
    MigLayout class references net.miginfocom.layout.LC (which lives
    in core) at construction time. Without BOTH jars the client module
    fails to compile with "cannot access net.miginfocom.layout.LC".
  - Properly implemented the five additional abstract methods declared
    on TransmissionModeClientProvider (Mirth 4.5+) that v1.1.4 missed:
    getProperties(), getDefaultProperties(), checkProperties(),
    resetInvalidProperties(), getSettingsComponent().
  - Updated pom.xml, client/pom.xml, and distribution/build.sh to
    declare miglayout-core and miglayout-swing 4.2 dependencies.

v1.1.4
  - Added the required getSampleLabel() override.
  - Changed send(OutputStream, InputStream, byte[]) ->
    send(OutputStream, InputStream, String) to match the parent's
    abstract method signature. String is converted to bytes
    internally using ISO-8859-1.

v1.1.3
  - Fixed wrong base class names:
      * server/ASTME1381TransmissionModePlugin now extends
        TransmissionModeProvider (server-side, was TransmissionModePlugin).
      * client/ASTME1381TransmissionModeClientPlugin now extends
        TransmissionModePlugin (client-side, was TransmissionModeClientPlugin).
      * Deleted server/ASTME1381ServerProvider.java (extended a
        non-existent TransmissionModeServerProvider; the receive flow
        already lives in ASTME1381StreamHandler.read()).
      * Added required createProvider() override on the client plugin.
  - Removed phantom @Override annotations on methods not declared on
    the actual parent classes.

v1.1.2
  - Removed phantom @Override from getPropertyDescriptors() and
    setProperties(Map) on ASTME1381TransmissionModeProperties.
    These methods are NOT declared on Mirth's
    TransmissionModeProperties base class (they belong to
    PropertyVerifier, used by DataType plugins). They are kept as
    plain methods on the subclass (used by the settings panel).

v1.1.1
  - Added donkey-server.jar to the IntelliJ mirth-server library
    (it contains com.mirth.connect.donkey.util.purge.Purgable,
    which TransmissionModeProperties implements). Without it the
    shared module fails to compile with "cannot access Purgable"
    followed by a cascade of @Override errors.
  - Added module-level pom.xml files (shared, server, client, test).
  - Added stubs/ directory with a compile-time-only Purgable
    interface for environments where donkey-server.jar is unavailable.
  - Replaced getPluginPointName() (inherited from Purgable) with
    ASTME1381Constants.PLUGIN_NAME directly in getPurgedProperties().
  - Switched setProperties(Map) to the parameterized
    Map<String, DataTypePropertyDescriptor> signature.

v1.1.0
  - Production hardening: bounded ENQ timeout, cap on consecutive
    NAKs, thread-safe RetryMetrics, per-phase configurable timeouts,
    Log4j structured logging, null-safe property parsing, defensive
    copies of frame payloads, 30 JUnit tests.
  - Moved ASTME1381TransmissionModeProperties, ASTME1381Frame,
    ASTME1381FrameException, ASTME1381RetryMetrics to the shared
    module (they were in server/ but used by client/).
  - Moved ASTME1381ClientProvider from server/ to client/.
  - Fixed transmissionmode.xml and plugin.xml class/jar references.

v1.0.0 (original release)
  - Multiple inconsistencies prevented compilation and deployment.
  See git history for details.

============================================================
BUILD PREREQUISITES
============================================================

To compile this project you need the following Mirth Connect 4.5+
jars at ../mirth-libs/:

    mirth-libs/server/mirth-server.jar
    mirth-libs/server/donkey-server.jar       <-- CRITICAL: contains Purgable
    mirth-libs/client/mirth-client.jar
    mirth-libs/client/mirth-client-core.jar   <-- contains TransmissionModeProperties
    mirth-libs/client/miglayout-core-4.2.jar  <-- CRITICAL: contains net.miginfocom.layout.LC
    mirth-libs/client/miglayout-swing-4.2.jar <-- contains net.miginfocom.swing.MigLayout
    mirth-libs/test/junit-4.13.2.jar
    mirth-libs/test/hamcrest-core-1.3.jar

CRITICAL JARS (build will fail without these):
  - donkey-server.jar   -> missing it causes "cannot access Purgable"
  - miglayout-core-4.2  -> missing it causes "cannot access LC"

If you genuinely cannot obtain donkey-server.jar, the project ships
a compile-time-only stub at stubs/com/mirth/connect/donkey/util/purge/
Purgable.java. Add the stubs/ directory to your IDE compile source
roots to compile; the real class is still required at runtime.
See stubs/README.md for details.

============================================================
BUILD
============================================================

1. Extract this zip to your workspace:
     unzip bitdreamit-astm-e1381-transmission.zip
     cd bitdreamit-astm-e1381-transmission

2. Provide Mirth Connect 4.5+ jars at ../mirth-libs/ (see above).

3. Build using one of:

   a) IntelliJ IDEA:
        File -> Open this directory
        Build -> Rebuild Project (Ctrl+Shift+F9)
        The .idea/libraries/*.xml files already wire up the jar paths
        listed above; just make sure the files exist on disk.

   b) Shell script:
        cd distribution && ./build.sh
        # outputs jars to ../out/
        # subcommands: clean, build, test, rebuild

   c) Maven:
        mvn -Dmirth.libs=$HOME/mirth-libs clean package

4. Output jars in ../out/:
     bitdreamit-astm-e1381-transmission-shared.jar
     bitdreamit-astm-e1381-transmission-server.jar
     bitdreamit-astm-e1381-transmission-client.jar

============================================================
DEPLOY TO MIRTH CONNECT
============================================================

  MIRTH_HOME=/opt/mirth-connect
  EXT_DIR=$MIRTH_HOME/extensions/bitdreamit-astm-e1381-transmission

  mkdir -p $EXT_DIR
  cp out/*.jar $EXT_DIR/
  cp transmissionmode.xml $EXT_DIR/
  cp server/resources/plugin.xml $EXT_DIR/server-plugin.xml
  cp client/resources/plugin.xml $EXT_DIR/client-plugin.xml

  # Restart Mirth service
  sudo systemctl restart mirth-connect

After Mirth restarts, the new "ASTM E1381" transmission mode will
appear in the channel editor under:
  - TCP Listener -> Transmission Mode
  - TCP Sender   -> Transmission Mode

See PRODUCTION.md for monitoring / operations guidance.
